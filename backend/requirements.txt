# --- RAG stack ---
#
# pypdf, not PyMuPDF. PyMuPDF binds MuPDF, a full rendering engine: it can
# rasterize pages, and it carries a large native library resident in the process
# for the whole run. We only ever called get_text(). pypdf is pure Python, reads
# one page object at a time, and never allocates a pixmap. Text quality on
# two-column layouts is slightly worse -- that is the cost, and it is stated in
# the README rather than hidden.
pypdf==5.1.0

# numpy does the vector search. There is no vector database in this process any
# more: chromadb kept an HNSW index and a Rust core resident, which is a large
# fixed cost to search a few hundred vectors per paper. Embeddings are stored as
# float32 blobs in SQLite and cosine similarity is one np.dot over one paper's
# matrix -- under a millisecond, and nothing stays resident between requests.
numpy==2.2.1

rank-bm25==0.2.2
# google-genai, not google-generativeai. The old SDK is deprecated and spoke
# gRPC; measured in-process the swap saved ~13 MB of resident floor and removed
# the gRPC core entirely. See app/rag/llm.py.
google-genai==2.23.0

# Reports current RSS for /debug/memory. Small, no native build on linux/win.
